# 事件編輯器（自己加人物・背景・文字）

一個單檔網頁工具：**左邊排場景、中間看畫面、右邊換人物背景寫台詞**，按一下播放就是一段劇情。

```
sc-editor/
├─ index.html   ← 編輯器本體（編輯 + 播放都在裡面）
├─ demo.json    ← 6 個場景的示範，可直接匯入
└─ README.md
```

---

## 30 秒上手

1. 雙擊 `index.html`。
2. 按工具列的 **＋ 新增場景**。
3. 右側面板：
   - **背景** →「本機圖片」選一張，或「素材站 ID」填 `00001`（直接抓遊戲背景）。
   - **人物** → 左／中／右 任一欄按「上傳」，選一張**透明背景 PNG**。
   - **台詞** → 填說話者和內容。
4. 按 **▶ 播放**，點畫面一句一句看。

想先看效果：**匯入 JSON** → 選 `demo.json`（6 個場景，含左右兩個人物的畫面）。

## 介面

參考「Gakumas Player」那類工具的骨架：**左場景序列／中播放器預覽／右屬性檢視**，
配色是灰階黑白（不是照抄它的顏色，只借結構）。

```
┌─────────────────────────────────────────────────────────────────┐
│ ✦ 事件編輯器 EVENT EDITOR  ● 狀態   素材牆 說明 保存 清除 匯出 JSON │
├──────────────┬────────────────────────────────┬─────────────────┤
│ SEQUENCE 1/3 │ PREVIEW   舞台 ─○ 名字 ─○ 台詞 ─○ │ INSPECTOR       │
│ ① 台詞…      │ ┌────────────────────────────┐ │ 01 基本信息     │
│ ② 台詞…      │ │  背景 ＋ 人物 ＋ 對話框     │ │ 02 背景         │
│ ③ …          │ └────────────────────────────┘ │ 03 角色與畫面   │
│ ＋ 新增場景  │ 04/06 ─────── 自動 ▶ 播放      │    五個位置     │
│ 6 場景 5 人物│                                │ 04 提示         │
│ PROJECT      │                                │                 │
└──────────────┴────────────────────────────────┴─────────────────┘
```

- 右欄順序調整為**基本信息 → 背景 → 角色與畫面 → 提示**，換背景不用先滑過五個人。
- 左欄底部有**場景／人物／台詞統計**，清單結尾有虛線的**＋ 新增場景**。
- 舞台空白時會顯示**「從這裡開始」**，可直接按「選擇背景」或「放入人物」。

- **一個場景 = 一張背景 ＋ 最多五個人 ＋ 一句台詞**，左邊序號卡就是時間軸。
- 點卡片切換；`複製` / `刪除` / `上移` / `下移` 作用在選中的場景。
- 中間預覽：`舞台`（整體縮放）、`名字`、`台詞` 三個滑桿即時調整，說話者與台詞**分開調大小**；`播放` 進全螢幕、`下一段`／`上一段` 手動推進、`自動播放` 會按字數自己前進。
  - 按 **播放** 時：每一段的**動作／表情會從頭重播**（講話維持循環），台詞以 **120ms／字** 逐一出現，點畫面可立刻顯示整句；**字幕打完後嘴巴會「把這一輪講完、閉嘴」才停止**，下一段才重新開始。
  - **按播放會自動進全螢幕**（佔滿螢幕、隱藏提示條）；如果瀏覽器擋下，按播放列或提示條上的 **⛶ 全螢幕** 再試一次。按 Esc 結束播放。
  - **轉場**：基本信息多了「轉場」下拉（無／黑場／白場／只淡入背景／溶接）＋時間（100–1500ms）。溶接 = 舊背景蓋在上面淡出、新背景同時出現（參考影片的換場），轉場期間文字框會先隱藏、人物淡入。匯出的官方腳本會帶 `effectLabel`／`bgEffect`／角色淡出 `charEffect`。
- 右邊屬性：上方是說話者、對話框（無／偶像／P）、台詞，接著是**背景**，再往下才是五個位置（最左／左／中／右／最右）的素材庫、上傳、網址、清除、動作與縮放。
  - **大小**：滑桿右邊有數字框，可以直接打數字（50–160），五個人物都填同一個就是統一尺寸。
  - **位置**：另一組「位置」滑桿／數字框（0–100%），可微調每個人站的位置。
  - CAST 標題右邊有 **「平均分配」**：一鍵把已放置的人物平均散開（1 人置中、2–3 人 20–80、4–5 人 12–88）。

### 中文台詞自動翻日文（內建翻譯器）

按「生成配音」時：

1. 台詞若**沒有假名**（中文）→ 先呼叫本機 API 的 `/ai/chat`（DeepSeek，Key 在 `D:\語音模型\ai_config.json`）翻成日文
2. 翻譯結果存進 `scene.voice.ja`（JSON 會帶著），再送 Irodori 合成
3. 同一句再生成時直接重用翻譯，不重翻（`voice.jaSrc` 對比原文）
4. 台詞本身已是日文（含假名）→ 跳過翻譯

失敗時：翻譯錯誤會顯示在配音列，**不會**把中文硬送進 TTS。

> 注意：deepseek-flash 是推理模型，思考內容會吃 token；翻譯固定給 2000 token，	ext 仍為空時自動改用 deepseek-chat 重試一次。

## 風格 Agent API（8090）

把「語體規格 + 官方語料檢索 + 翻譯/改寫 + 語氣配音」包成一支 HTTP 服務：

```powershell
# 啟動（或雙擊 agent\啟動AgentAPI.bat）
D:\irodori\src\Irodori-TTS-main\.venv\Scripts\python.exe D:\事件編輯器\agent\style_agent_api.py --port 8090
```

| 端點 | 說明 |
|---|---|
| `GET /health` | 29 角色、3110 位官方語料 speaker |
| `GET /style/card?speaker=月岡戀鐘` | 該角色規格＋自動推算的語速／口調 |
| `POST /style/check` | `{speaker, ja}` → 違規清單＋量測 |
| `GET /corpus/search?speaker=&q=&k=` | 從官方台詞檢索相似句 |
| `GET /models` `GET /voices` | 代理 8088 的清單 |
| `POST /tts/line` | 主端點：中文 → 日文（風格 agent）→ 配音 |

`POST /tts/line`：

```json
{"speaker":"月岡戀鐘","text":"製作人，今天要不要一起去吃拉麵？","emotion":"欣喜","with_audio":true}
```

回應：

```json
{"ok":true,"ja":"プロデューサー、今日一緒にラーメン食べに行かんばい？","rounds":1,
 "violations":[],"speech":{"duration_scale":0.97,"caption":"明るく砕けた博多弁で"},
 "model":"月岡戀鐘","voice":"kogane","audio_b64":"...","audio_bytes":445484,"elapsed":34.8}
```

流程：DeepSeek 初稿 → 規則量測 → 不合格就檢索官方相似句＋違規清單重寫（最多 2 輪）→ 切模型 → Irodori 配音（帶語速與口調）。

## 角色語體：照官方統計翻譯

`翻译参数表.md`（29 位角色的官方劇本統計）已轉成 **`sc-editor\style-spec.json`**，翻譯時自動套用：

| 欄位 | 用途 |
|---|---|
| 語体／敬語率 | 平语型不能用太多 です・ます |
| 一人稱 | 私／うち／わたし…必須一致 |
| 句長（中位） | 過長會被判定 |
| 句尾前六／頻率 | ！…？～ 的比例 |
| 稱呼 | 對製作人、其他角色的叫法 |
| 方言／角色形式 | 博多弁「ばい・やけん」、武人腔「だな・であろう」、っす体、古風敬語 |
| 禁止形式 | 例如戀鐘不能用「だね・だよ」 |
| 官方範例 | 給 LLM 的 few-shot |

**流程**：中文台詞 → 風格 prompt → DeepSeek 翻譯 → 規則檢查（禁止語尾／角色形式／一人稱／句長／敬語比例）→ 不合格就帶違規清單重翻一次 → 送 Irodori。

檢查結果會存進 `scene.voice`：`styleOk`、`styleWarn`、`styleCard`；配音卡片會顯示「語體：角色」或「風格⚠原因」。

重新產生規格（改了 `翻译参数表.md` 之後）：

```powershell
python sc-editor\tools\build-style-spec.py
```

### 讓配音更像官方：語速與口調

翻譯時已套用角色語體；**發音**另外套用官方統計的語速：

| 參數 | 來源 | 例子 |
|---|---|---|
| `duration_scale` | `4.5 ÷ 官方字/秒`（夾在 0.82–1.30） | 田中摩美美 3.63 → **1.24x**（慢）；八宮巡 5.08 → **0.89x**（快） |
| `caption` | 語体＋方言＋敬語率 | 博多弁 →「明るく砕けた博多弁で」；武人腔 →「落ち着いた武人らしい口調で」 |

實測同一句：

| 角色 | duration_scale | 長度 |
|---|---|---|
| 田中摩美美 | 1.00 | 4.44 秒 |
| 田中摩美美 | 1.24 | **5.52 秒**（×1.24，符合預期） |
| 八宮巡 | 0.89 | 3.00 秒 |

### 字體

台詞區有「字體」下拉，預設 **微軟雅黑**：

| 模式 | 用什麼 | 說明 |
|---|---|---|
| **微軟雅黑**（預設） | `Microsoft YaHei` Bold | 跟遊戲漢化截圖一致（漢化版沒帶字型，落到系統簡體字型） |
| 阿里巴巴數黑 | `AlimamaShuHeiTi` | 官方 EventViewer 用的中文字型；偏硬、較窄，「一」較細 |
| 微軟正黑 | `Microsoft JhengHei` Bold | 繁體向，標點是全形（逗號後面空白較大） |
| 圓體 | `YouYuan`（系統字型） | 系統內建圓體（簡體字庫） |
| **Humming** | `primula-HummingStd-E.woff2` | enza 原版日文對話字（JIS 字庫） |
| **UDKakugo** | `primula-UDKakugo_SmallPr6-B.woff2` | enza 原版粗黑體（JIS 字庫） |
| **Yuanti** | `yuanti.woff2` | enza 原版圓體（簡體字庫） |

> 三個原版字型已內嵌在 `素材\fonts\`，用 `@font-face` 載入，換電腦也不會掉。
>
> **繁體字說明**：enza 三個字型只有日文（JIS）與簡體字庫，沒有完整繁體字。繁體字會落到 微軟正黑，所以同一句若混到字庫外的字，看起來會是「正黑」。要讓繁體也有圓體效果，需要另外提供繁中字型檔（例如源柔ゴシック TC、jf open 粉圓）。

會記在 `localStorage`，下次開還是同一個模式。

> 判斷依據：把同一句「五年前，真乃和制作人结婚…」在三個字型下各排一次，
> 跟使用者截圖併排比對——雅黑的字寬、圓角與逗號位置最接近。

### 背景音樂（BGM）

左欄 PROJECT 區有一張 **背景音樂** 卡片：顯示目前曲目（名稱 · 長度 · 格式）、「已啟用」標記、
▶ 試聽鈕，以及 **管理背景音樂** 按鈕（開彈出視窗，不會跳去別頁）。

彈窗裡可以：

- **選擇音樂檔案**（MP3／WAV／OGG，可多選；音樂會內嵌進 JSON，跟圖片一樣自帶著走，檔案會變大）
- **播放設定**：音量（0–100%）、淡入時間（0–8 秒）、淡出時間（0–10 秒）
- **播放範圍**：整個作品播放，或指定「第 X 場景到第 Y 場景」
- **取消** 會還原這次打開彈窗後的所有改動；**儲存設定** 才生效

每個場景自己控制音樂：右欄 **基本信息 → 音樂** 下拉（轉場下面）：

| 選項 | 行為 |
|---|---|
| `沿用作品設定` | 繼續播作品的背景音樂（預設） |
| `暫停背景音樂` | 淡出並暫停，之後的場景也安靜直到再指定 |
| `切換：〈曲目〉` | 從這個場景起改播清單裡的某一首（淡出舊曲、淡入新曲） |

按 **▶ 播放** 時：BGM 從第一個場景開始（音量淡入）、換場景時按上面規則接續或切換、
播放結束自動淡出收掉。「指定場景範圍」之外的場景不會有音樂。

**匯出 JSON** 現在是 `{version, bgm, scenes}` 的包（音樂一起帶走）；匯入時舊格式
（純場景陣列）照樣能讀，只是沒有音樂。「保存／讀取上次」同樣會保存音樂設定。

### 語音配音（TTS）

「作品級 TTS 管理 + 角色級聲線控制」，全部走**統一的語音生成接口**，台詞編輯器不用知道底層是哪一種模型：

**雲端 TTS（API 適配）**
- 左欄「語音配音」卡片 → **管理語音服務**：ElevenLabs／Azure Speech／自訂 API（OpenAI 相容）三種供應商，填 API Key 後「儲存並測試」會實際合成一句測試音。
- **API Key 只存在本機伺服器的 `tts-keys.json`**，瀏覽器前端與匯出的 JSON 都不會帶 Key（由本機伺服器代理呼叫）。

**角色聲線（每個說話者用哪個供應商、哪個聲線）**
- 彈窗的「角色聲線」區會列出作品裡出現過的說話者，逐位指定供應商與聲線（Voice ID／語音名稱）。
- 同一個作品可以混合不同供應商配音。

**在台詞區使用**
- 右欄台詞下方有「**生成配音**」：依說話者的聲線設定，把這句台詞送到統一接口，音檔快取到 `sc-editor\tts-cache\`（同內容不會重複生成）。
- 生成是**背景工作**：按下去之後伺服器立刻接單（前端每 2 秒問一次結果），不會因為長時間合成斷線；失敗原因會寫在配音欄。
- 生成完自動試聽；配音欄有「▶ 播放配音／清除」，有配音的場景在左邊列表會標「♪配音」。
- 按 **▶ 播放** 時，每個場景會自動播放自己的配音。
- **BGM 與語音同時播放**：語音出現時背景音樂會自動壘低到 25%、語音結束自動恢復（遊戲常見的 ducking）。
- **匯出 JSON 時語音會自動內嵌成 dataURL**（跟圖片同一套），
  一個檔案自帶全部音檔，丟到別台電腦聲音照樣在；代價是 JSON 會變大（一句台詞約 300–600 KB）。

> 統一 TTS Request 的形狀：`{ source, provider, model, text, voice, emotion, speed, seed, format }`
> —— 未來要接回本地語音模型，只要在伺服器端加回 adapter 即可。






### 官方腳本格式（給播放器用）

專案區多了 **匯入官方／匯出官方** 兩顆按鈕。官方格式是一條扁平的 step 陣列：

```json
[
  { "textFrame": "002", "bg": "00001" },
  { "id": 4901000000000, "speaker": "プロデューサー", "text": "よし、始めよう。", "textFrame": "002" },
  { "textFrame": "001", "charLabel": "idol003", "charType": "characters",
    "charId": "003", "charPosition": { "x": 568, "y": 640, "order": 0 } },
  { "id": 4901000000001, "speaker": "八宮めぐる", "text": "はい、いつでも大丈夫です！", "textFrame": "001" }
]
```

| 我們的場景欄位 | 變成 | 說明 |
|---|---|---|
| 背景 | `{ bg: "00001" }` | 用 `素材/背景/rename-map.json` 的原始 ID |
| 人物（骨骼） | `{ charLabel, charType:"characters", charId, charPosition }` | `charId` 查 `素材/characters.json`；左右中 → x=284/568/852、y=640 |
| 說話者＋台詞 | `{ id, speaker, text, textFrame }` | `id` 由序號生成（4901000000000+i） |
| 對話框 | `textFrame` | 無框 `off`、粉 `001`、藍 `002` |

匯入時反向處理：`bg` 開新場景並沿用人物、`charId` 換成素材庫裡的骨骼、`text` 生成一句；
背景相同不會重複寫背景步驟，同一場景有兩句台詞會自動拆成兩個場景。

順手處理兩件事：

- **亂碼自動修**：官方腳本若是 UTF-8 被當 Latin-1 解過（`ãããã…`），匯入時會自動還原成日文。
- **靜態圖片人物不會進官方檔**：官方格式只有 `charId`，沒有「貼一張 PNG」的概念，所以只用骨骼角色才匯得出去。

範例：`docs/official-sample.json`。

### 素材庫（一鍵選圖，不用貼網址）

背景區和每個人物欄都多了一顆 **「素材庫」**：

- **在縮圖上按滑鼠右鍵**可以放大預覽（不會套用、不會關掉素材庫）；點一下畫面或按 `Esc` 關閉。
- 背景：1,118 張遊戲背景，縮圖牆直接挑
- 人物：**enza 立繪 2,235 套**（1,217 站姿 + 1,018 換裝），選了就會動，下面多一個動作下拉選單
  - 動作下拉分三組：**常用動作**（wait／smile／sad／surp／anger／shy…）、**表情差分**（face_*／lip_*）、**骨骼零件**（bone／hair 等）
  - 一套骨架通常 60–200 個動作；「驚訝」是 surp1／surp2／face_surp
  - **動作與表情可同時用**：動作播在 track 0、表情（face_*／lip_*）播在 track 1，兩者疊加
  - **表情／講話是兩個獨立下拉**：表情放 track 1（face_*，單次）、講話放 track 2（lip_*，循環），可同時用（例如「微笑 + 講話」）
  - 講話速度由 TALK_SCALE（預設 0.85）控制，越小越慢
    - **情緒預設**：每張人物卡有一排 9 個文字按鈕（平靜／開心／營業／害羞／驚訝／生氣／委屈／思考／嘆氣），按一下同時設定動作＋表情；缺動作時會自動退回該骨架有的近似動作
  - **一直往下捲就好（人物）**：一次先放 60 套，捲到底自動續接，不需要一頁一頁翻；底部顯示「已顯示 N / 總數」。
  - **背景是頁數模式**：每頁 60 張，底部有 `1 2 3 … 19` 頁碼與 `◀ 上一頁 / 下一頁 ▶`，開啟時會自動跳到目前使用中背景的那一頁。
  - 素材庫上方有**角色分類列**（各角色，附套數，沒有「全部」），點一下只顯示該角色；打開時會自動選中目前角色（空白位置則沿用上次選的角色），沒有指定時停在第一位。
  - **角色群組標題**：列表裡「站姿／換裝」各有黏在頂端的標題，捲再遠也知道現在看的是哪一類。
  - **站姿／換裝篩選**：列表左邊的 `全部／站姿／換裝`，只想找服裝或只想找站姿時按一下；換裝卡左上角另有「換裝」小標。
  - **搜尋跨角色**：空格分隔多個關鍵字（例：`真乃 103001`），角色名、服裝編號、站姿／換裝都算；一打字就直接在全部 2,235 套裡找，不用先切角色，篩選列會提示「正在全部角色中搜尋」。
  - **縮圖大小**：右上 `小／中／大`，會記在瀏覽器；一次想看更多就切「小」。
  - **放入位置**：`放入：最左 左 中 右 最右`，不用關素材庫就能換要放哪一格（橘點表示那格已經有人）。
  - **套用後不關**（勾選後）：按角色只會套用、素材庫保持打開，可以接著放進下一個位置；「使用中」會跟著移到剛套用的那張。
  - **鍵盤**：方向鍵在縮圖牆移動，Enter 套用，Esc 關閉。
  - **會停在目前使用中的那一套**：再打開時自動捲到該張（必要時先補載入），並標上橘框「使用中」。
  - 舊的「靜態圖／骨骼動畫」分頁與素材（`素材/立繪`、`立繪_spine`、`spine`）已移除

**骨骼動畫需要開 http**（PIXI 要用 fetch 讀骨架）：

- 雙擊上層資料夾的 **`啟動編輯器.cmd`** —— 伺服器會在**背景**啟動（沒有黑色視窗），
  瀏覽器自動打開編輯器；重複雙擊會沿用已經在跑的伺服器。
- 要收掉背景伺服器：雙擊 **`停止伺服器.cmd`**（不收也沒關係，關機時會自動結束）。
- 也可以手動：`powershell -ExecutionPolicy Bypass -File ..\start.ps1`（加 `-Stop` 停止）。

用 `file://` 直接雙擊時，「骨骼動畫」分頁會提示改用 http；靜態圖那頁照常可用。

資料來源是 `../素材/index.json`；**讀不到時會自動改用 `../素材/index.js`**，
所以直接雙擊 `index.html`（`file://`）也能用，不一定要開伺服器。

素材有增減後，重新產生索引：

```powershell
.\素材\build-index.ps1
```

⚠️ 用素材庫選的圖存的是**相對路徑**（`../素材/…`），在 `D:\事件編輯器` 這個結構下都很正常；
但匯出的 JSON 拿到別台電腦、或素材資料夾沒一起搬，圖就會不見。
要「一個檔案帶著走」請用「本機圖片」上傳（會內嵌成 dataURL）。

## 存檔

- **保存**（工具列右上，或 `Ctrl`+`S`）：把目前整份劇本存成 `sc-editor/saved-project.json`，瀏覽器也留一份。
  下次開啟會**自動載入上次保存的內容**（檔案與瀏覽器兩份取比較新的）。
- **清除**（保存旁邊）：刪掉上次保存的劇本（檔案與瀏覽器各一份），目前畫面上的內容不受影響；刪掉後下次開啟就是全新的一份。
- **讀取上次**（左欄 PROJECT 標題旁）：改壞了想退回上次保存的版本時按它，會先詢問再覆蓋目前內容。
- **要重新開始**：按左欄「清空」再保存一次，就會覆蓋上一份。
- **匯出 JSON**：要備份、換電腦、分享就用這個（完整帶走圖片）。
- **匯入 JSON**：讀回來或手改後再載入。
- 圖片是用 **dataURL 內嵌**在 JSON 裡（所以檔案自帶素材，換電腦不會掉圖），代價是檔案變大：一張立繪通常幾百 KB。

> 只有「字體」這個偏好會記在 `localStorage`，其餘一律不記。

## JSON 格式

```json
[
  {
    "bg": { "name": "bg 00001", "src": "https://viewer.shinycolors.moe/images/event/bg/00001.jpg" },
    "chars": {
      "left": null,
      "center": { "name": "madoka.png", "src": "data:image/png;base64,....", "scale": 1 },
      "right": null
    },
    "speaker": "円香",
    "text": "……そうですか\r\n（二行目）"
  }
]
```

| 欄位 | 說明 |
|---|---|
| `bg` | `null` = 全黑；`src` 可以是 dataURL 或 https 網址 |
| `chars.left/center/right` | `null` = 這一位不在場；否則 `{ name, src, scale }` |
| `scale` | 0.5 ～ 1.6，預設 1 |
| `speaker` | 可留空（純旁白） |
| `text` | `\r\n` 或 `\n` 換行 |

## 進階

- **Console 批次操作**：頁面有開 `window.__editor`
  ```js
  __editor.load([{ bg: null, chars: {}, speaker: '我', text: '第一句' }]);
  __editor.state.scenes.length   // 目前場景數
  ```
- **想加語音／音效**：場景物件加 `"voice": "https://…/xxx.m4a"`，再在 `paint()` 裡 `new Audio(src).play()` 即可（程式碼裡有現成的圖片載入可對照）。
- **想要立繪會動、轉場特效、遊戲原始事件**：那是另一條線，看上一層的 [`sc-viewer/README.md`](../sc-viewer/README.md)。

## 已知限制（先講清楚，免得你以為壞了）

1. **沒有語音／音效／BGM**，目前是純視覺＋文字。
  - **轉場**：基本信息多了「轉場」下拉（無／黑場／白場／只淡入背景／溶接）＋時間（100–1500ms）。溶接 = 舊背景蓋在上面淡出、新背景同時出現（參考影片的換場），轉場期間文字框會先隱藏、人物淡入。匯出的官方腳本會帶 `effectLabel`／`bgEffect`／角色淡出 `charEffect`。
3. **骨骼動畫必須用 http 開**（`file://` 雙擊只有靜態圖）；換一套服裝會重新載入骨架，大約 1 秒。
4. 骨架是 spine **3.6** 格式、跑在 pixi-spine **3.7** 上；之後若換 4.x 骨架要換 runtime。
5. 背景「素材站 ID」只支援數字 ID；背景圖本身仍需要連網。
6. 圖片壓縮到最長邊 1280px；要更高畫質請自己先裁好再上傳（但仍會被壓）。
